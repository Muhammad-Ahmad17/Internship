
# **AWS EC2 Launch Template Guide**

## **1. What is an EC2 Launch Template?**

An **EC2 Launch Template** is a resource in AWS that allows you to **predefine configuration settings** for launching EC2 instances. Think of it as a “blueprint” for your EC2 instances.

Instead of manually configuring instances every time, you store all necessary parameters in a template, which can include:

* AMI (Amazon Machine Image) ID
* Instance type
* Key pair
* Security groups
* Network/subnet
* IAM role
* Storage volumes
* User data scripts (for automation)
* Tags
* Monitoring and more

**Benefits:**

* **Consistency:** Launch multiple instances with identical configurations.
* **Automation:** Easily integrate with Auto Scaling Groups or AWS CLI scripts.
* **Versioning:** Manage multiple versions of templates for different environments.

---

## **2. Key Concepts**

* **Launch Template Name:** Unique name for the template.
* **Version:** Each template can have multiple versions. New versions allow updates without affecting running instances.
* **Overrides:** You can override certain parameters when launching instances from a template.
* **Compatibility:** Launch templates can be used with EC2, Auto Scaling Groups, Spot Fleet, and EC2 Fleet.

---

## **3. Steps to Create a Launch Template**

### **Step 1: Open the EC2 Console**

1. Login to AWS Console → Services → EC2 → Launch Templates → **Create launch template**.

### **Step 2: Provide Template Details**

* **Template Name:** e.g., `MyAppServerTemplate`
* **Description:** Optional, e.g., “Launch template for web server instances”
* **Resource Tags:** Add tags like `Environment=Production`

### **Step 3: Choose an AMI**

* Select the AMI ID for your instance (Amazon Linux, Ubuntu, Windows, etc.)

### **Step 4: Choose Instance Type**

* Example: `t3.medium`, `m5.large`, etc.

### **Step 5: Key Pair**

* Select a key pair for SSH/RDP access.
* **Important:** Without this, you cannot access the instance remotely.

### **Step 6: Configure Network Settings**

* **VPC/Subnet:** Choose the subnet to launch instances in.
* **Auto-assign Public IP:** Enable if instance needs public internet access.

### **Step 7: Security Groups**

* Attach existing security groups or create a new one.
* Example rules:

  * SSH (TCP 22) for Linux
  * RDP (TCP 3389) for Windows
  * HTTP (TCP 80) or HTTPS (TCP 443) for web servers

### **Step 8: Storage (EBS)**

* Configure root and additional EBS volumes.
* You can set volume size, type, and delete-on-termination behavior.

### **Step 9: Advanced Options (Optional)**

* **IAM Role:** Attach roles to grant permissions to AWS services.
* **Monitoring:** Enable CloudWatch detailed monitoring.
* **User Data:** Add startup scripts for automation, e.g., install Apache, deploy code.

### **Step 10: Review & Create**

* Check all settings → Click **Create launch template**.

---

## **4. Launch an EC2 Instance from a Template**

You can launch directly via **Console, CLI, or Auto Scaling Groups**.

### **Console**

1. Go to EC2 → Launch Templates → Select your template → **Actions → Launch instance from template**
2. Optionally override:

   * Instance type
   * Subnet
   * Key pair
3. Click **Launch instance**

### **CLI Example**

```bash
aws ec2 run-instances \
    --launch-template LaunchTemplateName=MyAppServerTemplate,Version=1 \
    --count 1
```

---

## **5. Versioning Launch Templates**

* Every change creates a **new version**.
* Versioning allows rollback or testing new configurations.

### **Create a new version**

1. Select template → **Actions → Create new version**
2. Update parameters → Save

### **Launch specific version**

```bash
aws ec2 run-instances \
    --launch-template LaunchTemplateName=MyAppServerTemplate,Version=2
```

---

## **6. Using Launch Templates with Auto Scaling**

* **Auto Scaling Groups** (ASG) can reference launch templates for consistent EC2 scaling.
* Benefits:

  * Automated horizontal scaling
  * Spot instance or On-Demand instance management
  * Version control for updates

---

## **7. Tips & Best Practices**

* **Always use versioning**: Keep track of changes for rollback.
* **Use tags**: Helps organize instances, especially in large deployments.
* **Use IAM roles, not credentials**: Avoid embedding AWS keys.
* **Include user-data scripts**: Automates instance setup on launch.
* **Monitor costs**: Launch templates can be paired with Spot instances for cost savings.

---

## **8. Common Issues**

| Issue                            | Fix                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------- |
| Cannot SSH/RDP                   | Check key pair, security group, and subnet public IP                            |
| User data not executing          | Ensure proper script syntax and `#!/bin/bash` (Linux) or `powershell` (Windows) |
| Launch template version mismatch | Specify correct version when launching                                          |

---

## **9. Summary Workflow**

1. Create a launch template → Define AMI, instance type, security, storage, user data.
2. Save template → Optionally create new versions for updates.
3. Launch instances from template → Either via console or CLI.
4. Use templates with Auto Scaling Groups for automated scaling.
5. Monitor and manage costs, security, and updates.

# **User data** 
In Advanced details box in launch template section there is a option of user data.
In AWS EC2 is a way to **provide startup instructions to an instance when it launches**. Basically, it’s a script or commands that automatically run **once, during the first boot** of the EC2 instance.

Think of it like giving your instance a checklist for “what to do when it starts.”

---

## **Key Points About User Data**

1. **Runs only on first boot** by default.
2. **Used for automation**, so you don’t have to manually configure the instance after launch.
3. **Supports multiple scripting languages** depending on the OS:

   * **Linux:** Shell scripts (`#!/bin/bash`)
   * **Windows:** PowerShell scripts (`<powershell>` tag or `.ps1` scripts)

---

## **Common Uses**

* Installing software packages
* Updating the OS
* Setting environment variables
* Configuring applications or services
* Pulling code from a repository

---

## **Examples**

### **Linux EC2**

```bash
#!/bin/bash
# Update the instance
yum update -y

# Install Apache web server
yum install httpd -y

# Start Apache service
systemctl start httpd
systemctl enable httpd

# Create a simple index.html
echo "<h1>Welcome to my EC2 instance!</h1>" > /var/www/html/index.html
```

### **Windows EC2 (PowerShell)**

```powershell
<powershell>
# Install IIS web server
Install-WindowsFeature -name Web-Server -IncludeManagementTools

# Create a simple HTML page
Set-Content -Path "C:\inetpub\wwwroot\index.html" -Value "<h1>Welcome to my EC2 instance!</h1>"
</powershell>
```

---

## **How to Add User Data**

1. **When launching a new instance via the console:**

   * Under **Advanced Details**, paste your script into the **User data** section.
2. **With Launch Templates:**

   * Add the script in the **User data** field when creating the template.

---

**Tip:**
You can combine user data with **cloud-init (Linux)** or **EC2Launch/EC2Config (Windows)** for more advanced automation.
