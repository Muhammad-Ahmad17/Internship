
# 🔹 **Instances**

* **Instances**:
  Virtual servers running in AWS. They are your actual machines (Linux, Windows, etc.) where apps run.

* **Instance Types**:
  Different hardware configurations (CPU, memory, storage, networking). Example: `t3.micro` (cheap, general use) vs `m5.large` (balanced compute).

* **Launch Templates**:
  Predefined configuration (AMI, instance type, security groups, etc.) used to launch EC2 instances quickly and consistently.

* **Spot Requests**:
  Spare AWS capacity at a much lower price (up to 90% cheaper). But AWS can reclaim it anytime → good for non-critical, batch jobs.

* **Savings Plans**:
  Commitment-based pricing (1 or 3 years) to get discounts (similar to Reserved Instances, but more flexible across instance families).

* **Reserved Instances**:
  1- or 3-year commitment for a specific instance type/region. Provides significant cost savings (up to 72%).

* **Dedicated Hosts**:
  Physical servers dedicated to your use only. Needed for compliance or licensing restrictions.

* **Capacity Reservations**:
  Reserve compute capacity in a specific AZ to ensure availability, without committing to pricing discounts.

---

# 🔹 **Images**

* **AMIs (Amazon Machine Images)**:
  Templates used to launch EC2 instances. Includes OS + optional software. Example: Ubuntu AMI, Windows AMI, or a custom AMI with your app pre-installed.

* **AMI Catalog**:
  Library of available AMIs (public, AWS marketplace, or private).

---

# 🔹 **Elastic Block Store (EBS)**

* **Volumes**:
  Virtual hard drives attached to EC2 instances. Persistent (data survives even if the instance stops).

* **Snapshots**:
  Backup of an EBS volume, stored in S3. Can be used to restore or create new volumes.

* **Lifecycle Manager**:
  Automates snapshot creation and retention policies (for backups, compliance).

---

# 🔹 **Network & Security**

* **Security Groups**:
  Virtual firewalls controlling inbound/outbound traffic to instances. Example: allow SSH (port 22), HTTP (port 80).

* **Elastic IPs**:
  Static public IPv4 addresses that you can attach to instances (so your server keeps the same IP even if it stops/starts).

* **Placement Groups**:
  Control how instances are physically placed within AWS data centers:

  * **Cluster**: close together (low latency, high throughput).
  * **Spread**: separate racks (better fault tolerance).
  * **Partition**: for large distributed systems (like Hadoop).

* **Key Pairs**:
  SSH keys used to securely connect to Linux instances (private key stays with you, public key on AWS).

* **Network Interfaces (ENIs)**:
  Virtual network cards for EC2. They define IP addresses, security groups, MAC addresses, etc. An instance can have multiple ENIs.

---

# 🔹 **Load Balancing**

* **Load Balancers (ELB)**:
  Distributes traffic across multiple EC2 instances → improves availability & fault tolerance.

* **Target Groups**:
  A collection of instances/containers that a load balancer routes traffic to. Supports health checks.

* **Trust Stores**:
  For SSL/TLS certificates. Store and manage trusted Certificate Authorities (CAs) used by load balancers.

---

✅ In summary:

* **Instances** = your servers.
* **Images** = server templates.
* **EBS** = storage/disks.
* **Network & Security** = firewalls, IPs, and networking.
* **Load Balancing** = traffic distribution and SSL management.
