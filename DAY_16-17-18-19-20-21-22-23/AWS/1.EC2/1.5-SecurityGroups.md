# 🔐 AWS EC2 Security Groups (with RDP Setup)

A **Security Group (SG)** in AWS is a **stateful, virtual firewall** that controls traffic **to and from** your EC2 instances.
---

---

## 📌 1. What is a Security Group?

- **Inbound Rules** → Control traffic *into* the instance (e.g., SSH, RDP, HTTP).  
- **Outbound Rules** → Control traffic *out of* the instance (e.g., updates, APIs).  
- **Stateful Nature** → If inbound traffic is allowed, the response traffic is automatically allowed, even if outbound rules don’t explicitly allow it.

> 🔑 Example: If you allow **TCP port 3389 (RDP)** inbound, the return RDP traffic is automatically permitted.

---

## 📌 2. Key Characteristics of Security Groups

- **Instance Level Firewall** → Applied directly to EC2 instances, not subnets (unlike NACLs).  
- **Multiple SGs per Instance** → You can attach multiple security groups to one instance.  
- **Multiple Instances per SG** → A single SG can be shared across many EC2s.  
- **Default SG** → Every VPC has a default SG that:  
  - Denies all inbound  
  - Allows all outbound  
  - Allows inbound traffic from **instances within the same SG**  

---

## 📌 3. Analogy (Simple Example)

Think of an EC2 as your **house**:

- **Inbound Rules** = Who can come into your house (friends, delivery).  
- **Outbound Rules** = Where your family can go outside (park, shop).  
- If you let someone in (inbound), they can also leave (stateful).  

---

## 📌 4. Default Behavior

- **Inbound:** Blocked by default.  
- **Outbound:** Allowed by default.  

This means:
- You must **explicitly allow inbound ports** like SSH (22), RDP (3389), or HTTP (80).  
- Outbound is open unless restricted.  

---

## 📌 5. Rule Structure

Each rule requires:  

- **Type** → Predefined (SSH, RDP, HTTP, HTTPS, etc.) or Custom  
- **Protocol** → TCP, UDP, ICMP, or ALL  
- **Port Range** → e.g., 22 for SSH, 3389 for RDP, 80 for HTTP  
- **Source/Destination** →  
  - `My IP` → Your current public IP  
  - `Custom` → Specific CIDR block (e.g., `203.0.113.25/32`)  
  - `Anywhere (0.0.0.0/0)` → Open to all IPv4 (⚠️ less secure)  
  - `::/0` → Open to all IPv6 (⚠️ less secure)  

---

## 📌 6. Example – RDP Access for Windows EC2

To connect from your **Linux system using Remmina (RDP)**, allow **TCP port 3389**.

### ✅ Inbound Rule (Allow RDP)
| Type | Protocol | Port Range | Source  |
|------|----------|------------|---------|
| RDP  | TCP      | 3389       | My IP   |

### ✅ Outbound Rule (Default)
| Type        | Protocol | Port Range | Destination |
|-------------|----------|------------|-------------|
| All traffic | All      | All        | 0.0.0.0/0   |

---

## 📌 7. Step-by-Step: Setup Security Group for RDP

1. Go to **AWS Console → EC2 → Instances**.  
2. Select your **Windows EC2 instance**.  
3. Scroll to **Security groups** → Click the linked group name.  
4. Click **Edit inbound rules** → Add:  
   - **Type:** `RDP`  
   - **Protocol:** `TCP`  
   - **Port Range:** `3389`  
   - **Source:** `My IP` (recommended) or `0.0.0.0/0` (not secure).  
5. Save changes.  
6. Now connect via **Remmina** on Linux → RDP to your instance’s **Public IP**.

## 📌 8. Security Group vs. Network ACL (NACL)

| Feature           | Security Group (SG)        | Network ACL (NACL)           |
|-------------------|----------------------------|-------------------------------|
| Scope             | Instance-level             | Subnet-level                 |
| Stateful?         | ✅ Yes                     | ❌ No                        |
| Default Inbound   | Deny all                   | Allow all                    |
| Default Outbound  | Allow all                  | Allow all                    |
| Rule Processing   | Evaluates all rules        | Evaluates in rule order      |
| Use Case          | Protect EC2 instances      | Additional subnet protection |

---

## 📌 9. Best Practices

- ✅ Use **“My IP”** instead of `0.0.0.0/0` for RDP/SSH.  
- ✅ Keep only **necessary ports** open.  
- ✅ Use **separate SGs per tier** (e.g., web, app, DB).  
- ✅ Regularly **review & clean up unused rules**.  
- ✅ Enable **VPC Flow Logs** for monitoring.  
- ✅ Use **Security Group references** (instead of IPs) for internal communication between tiers.  

---

## 📌 10. Common Issues & Fixes

| Problem                     | Cause / Fix                                                                 |
|------------------------------|-----------------------------------------------------------------------------|
| RDP/SSH not working          | Port not open in SG, or wrong IP in source rule                             |
| Timeout when connecting      | Instance has no Public IP / Elastic IP, or NACL blocking traffic            |
| Connection refused           | Service (RDP/SSH) not running inside instance                               |
| Can’t access web app         | HTTP/HTTPS ports not allowed in inbound rules                               |
